# LightAutoML: экспериментальный кандидат для регрессии

LightAutoML дополняет набор инструментов Qwen: это система обучения и объединения
табличных моделей, а не дополнительная LLM. Первая интеграция предназначена для
регрессии с временным разбиением. Классификация пока продолжает использовать
прежний путь и AutoGluon.

Кандидат получает тот же набор внешних временных фолдов, что и сохранённый
reference suite. Внешняя валидация нужна только для итогового RMSE: её строки и
таргеты не передаются в `TabularAutoML.fit_predict`. Внутри каждой обучающей части
выделяется самый поздний прошлый период для настройки. Предшествующие периоды
используются для обучения базовых моделей. Так внутренний ранний останов,
обработка категорий и веса собственного ансамбля LightAutoML не подглядывают
во внешний год.

Конфигурация использует один уровень `lgb`, `linear_l2`, `cb`, CPU и
отключённую дополнительную селекцию признаков. Это добавляет линейную модель и
иной способ обработки признаков к нашим бустингам. Алгоритмы с предобученными
весами не включаются. Конфигурации и возможности описаны в
[официальном шаблоне 0.4.2](https://github.com/sb-ai-lab/LightAutoML/blob/v.0.4.2/lightautoml/automl/presets/tabular_config.yml).

## Бюджет и экспорт

Бюджет задаётся на весь suite вместе: все внешние фолды, сохранение и финальный
пакет. Это не отдельный лимит на каждый алгоритм. Каждый запуск выполняется в
отдельном процессе с жёстким внешним ограничением времени. При ошибке или
исчерпании времени уже имеющийся reference остаётся пригодным для экспорта.

Mode `lightautoml` сохраняет preset с внутренним временным holdout: последний
период участвует в остановке/смешивании, но не в обучении базовых моделей.
Дополнительно `refit_full=True` создаёт парный mode `lightautoml_refit` через
наш адаптер для точной версии 0.4.2. В нём все удержанные компоненты обучаются
на всём доступном прошлом с замороженными внутренними параметрами, числом
деревьев / линейным C и весами смеси. Нет нового поиска, eval_set или train=valid.
Preprocessing заново fit на past; target encoding отключён. Внешний год виден
только predict. Оба финальных pipeline строятся внутри бюджета suite.

Preset сохраняется через joblib, загружается заново и должен воспроизвести те же
предсказания. `fit_predict(..., valid_data=..., path_to_save=...)` и
`predict(...).data` являются документированными интерфейсами.
[API](https://lightautoml.readthedocs.io/en/latest/pages/modules/generated/lightautoml.automl.presets.tabular_presets.TabularAutoML.html).

Проверять нужно три результата на одинаковых внешних строках: reference,
LightAutoML, заранее фиксированная смесь 50/50. Отдельно проигравший кандидат
может оказаться полезен в смеси. Выбирать внешние веса многократным перебором
по тем же фолдам не следует.

## Состояние окружения на 25 октября 2026

В `requirements.txt` уже указан `lightautoml==0.4.2`. В момент начала интеграции
пакет не установлен ни в `.venv_autogluon`, ни в общей базовой `.venv`. Также
отсутствовали Optuna, AutoWoE, holidays, json2html, cmaes, SQLAlchemy, tabm,
tabicl и poetry-core. Во время исследовательской проверки установки и обучения
не выполнялись.

Python 3.12 входит в заявленные версии. Наши основные версии NumPy, SciPy,
sklearn, PyTorch и бустингов удовлетворяют прямым ограничениям LightAutoML.
Текущий импорт и создание CPU-preset после установки проверены отдельно ниже.
[Метаданные точной версии](https://pypi.org/pypi/lightautoml/0.4.2/json).

Важно: preset 0.4.2 импортирует модуль TabICL на Python 3.9+, даже если обучать
TabICL не планируется. Поэтому установка только wheel LightAutoML с `--no-deps`
недостаточна. Нужен согласованный набор зависимостей с сохранением наших ML-пинов.
Импорт этого модуля не означает использование предобученной модели; выбранные
алгоритмы явно ограничиваются `lgb`, `linear_l2`, `cb`.
[Исходный код preset](https://github.com/sb-ai-lab/LightAutoML/blob/v.0.4.2/lightautoml/automl/presets/tabular_presets.py).

Запуск Qwen и оценку реального прироста выполняет пользователь. Новый backend
пока нельзя считать улучшением контрольного решения
по одному факту его подключения.

## Подготовленная отдельная среда

Создана `.venv_lightautoml` с Python 3.12.10 и собственным pip. Её `.pth` включает
готовые пакеты из `.venv_autogluon`, затем из `.venv`. Сами две существующие среды
не изменялись. Дополнительные зависимости следует устанавливать только в
`.venv_lightautoml`.

Зафиксированные текущие версии вынесены в
`work/lightautoml_core_constraints.txt`. Предварительный расчёт установки:

```powershell
.\.venv_lightautoml\Scripts\python.exe -m pip install --dry-run --report work/lightautoml_install_plan.json --constraint work/lightautoml_core_constraints.txt lightautoml==0.4.2
```

Первый расчёт был ограничен сетью sandbox. Повторный расчёт с доступом к PyPI
успешен: 26 дополнительных пакетов, без замены NumPy/SciPy/pandas/sklearn/PyTorch
и бустингов. Затем пакеты установлены только в `.venv_lightautoml` по этому плану.
В `work/lightautoml_install_plan.json` находится настоящий успешный отчёт pip.

После подготовки пакетов проверить импорт без обучения и без API можно так:

```powershell
.\.venv_lightautoml\Scripts\python.exe check_lightautoml.py
```

Импорт LightAutoML 0.4.2, создание Task и CPU-preset прошли проверку:
`controls/lightautoml_0_4_2_readiness.json`. Скрипт не читает данные хакатона
и не обучает модели. Сообщения об отсутствии NLP-пакетов не относятся к выбранным
табличным алгоритмам; ради них дополнительные модели не устанавливались.

## Первый запуск с Qwen

API-переменные должны быть заданы в этом же терминале. Запускаем отдельное
исследование без --resume: код и fingerprint изменились. Никакие результаты
старого запуска по одному имени каталога не принимаются за новые измерения.

```powershell
.\.venv_lightautoml\Scripts\python.exe champion_solution/solution_torch.py tasks/regression/task.md --output-dir outputs/champion_regression_lightautoml_v2 --threads 8 --researchers 1 --training-jobs 1 --reviewer --no-analyst --autogluon-budget 0 --flaml-budget 0 --lightautoml-budget 3600 --time-budget 9900 --max-steps 80 --step-timeout 3600 --instructions lightautoml_regression_plan.md
```

FLAML отключён только этой командой, чтобы сравнить добавление LightAutoML
отдельно. Общие defaults других инструментов не менялись. LightAutoML по
умолчанию выключен локально и на платформе, включается положительным бюджетом.
3600 секунд — суммарный потолок всех вызовов LightAutoML; план задаёт три
сравнения по 900 секунд, включая внешние fit и финальные pipeline. Остаток
не требуется тратить искусственно. Истинный расход сохраняется в ledger.

Основной CSV: `outputs/champion_regression_lightautoml_v2/submission.csv`.
Внутри `agent_runs/<run>`: lightautoml_summary.json, lightautoml_budget.json,
temporal/<suite>/report.json и final_selection.json / final_output.json.
Результаты сохраняются в общей истории Qwen. Отдельный проигрыш LAMA не запрещает
проверить равновесный ансамбль с его сырым режимом `lightautoml`.

Первый реальный запуск v1 завершился: прежний ансамбль mean RMSE 39.9274,
LightAutoML 42.9750, смесь с CatBoost 40.7270. LAMA потратил 62 из выделенных
1800 секунд. Это исходная точка, а не результат нового кода.

В v2 добавлены отдельные инструменты train_<algorithm> вместо общей схемы,
память детерминированных ошибочных запросов, feature_mode=compact_strings
(тот же компактный набор без числового хеширования категорий), bounded tuning
`lgb_tuned` / `cb_tuned` до 8 trials по плану (максимум 12 в инструменте) и
парное сравнение full-past refit. Все этапы отражаются в плане Qwen.

Восемь целевых коротких проверок прошли: параметры, повторные ошибки, временные
границы и экспорт отдельных режимов/ансамблей. Native refit отдельно проверен
на 240 искусственных строках для LinearLBFGS, LightGBM и CatBoost, включая reload.
Текущие реальные данные новым кодом и Qwen ещё не запускались.

В ZIP добавляются корневые lightautoml_research.py, lightautoml_refit.py и
training_contract.py; requirements уже содержал
lightautoml==0.4.2. Обязательных внешних JSON не добавлено. Архив v7, который
проверяется на платформе, не изменён.
