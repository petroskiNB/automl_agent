# FLAML в регрессионном агенте

Добавлен run_flaml_suite и локальный флаг --flaml-budget. По умолчанию FLAML
выключен, включая платформенный entry point: сначала проверяем локальный запуск.
Классификация и её AutoGluon не изменяют бюджет или инструкции этого инструмента.
Контрольный архив 2157.225 и сохранённые сравнения не перезаписаны.

FLAML 2.3.6 установлен в .venv без обновления остальных пакетов. Для другого ПК:

```powershell
.\.venv\Scripts\python.exe -m pip install "flaml[automl]==2.3.6"
```

## Результат первого локального запуска — 25 октября

Запуск agent_runs/20261025_151651_496164 завершился успешно за 3494.282 секунды.
Сам FLAML потратил 1475 секунд из бюджета 1800. На одинаковых внешних годах:

| Кандидат | Mean RMSE | Последний год | Худший год |
|---|---:|---:|---:|
| Исходный CatBoost + history_hierarchy | 40.701775 | 34.512274 | 52.377954 |
| FLAML | 42.200417 | 36.892239 | 57.169857 |

FLAML выбирал XGBoost / Extra Trees / LightGBM по годам. Экспортирован reference:
в финальный CSV вошёл исходный CatBoost, без FLAML. 22449 строк опубликованы;
контрольный архив не заменён. Один запуск не доказывает, что FLAML бесполезен
для других признаков, бюджетов или задач.

Дополнительная диагностика по сохранённым OOF-прогнозам, без обучения и изменения
выбора: равное усреднение reference+FLAML дало mean 40.529567. С прежним лучшим
контрольным ансамблем (39.927404) смесь FLAML дала 40.342873. Поэтому улучшения
нашего лучшего среднего результата пока нет. Это не зарегистрированные и не
экспортируемые пайплайны. Прежнее правило «проверять смесь только при одиночной
победе» пропускает полезную проверку; при дальнейшей доработке нужно разрешить
оценку фиксированной смеси с проигравшим, но отличающимся кандидатом.

Платформенный FLAML остаётся выключенным по умолчанию. Экспериментальный архив
v6.3 проверяет изоляцию регрессии с сохранённым AutoGluon для классификации,
а не подтверждённое улучшение FLAML. Исправление автоматического выбора и
экспорта завершённого classification/AutoGluon OOF-пайплайна сохранено.

## Первый запуск Qwen

Из корня проекта, в PowerShell с уже заданными OPENAI_API_KEY, OPENAI_BASE_URL
и OPENAI_MODEL:

```powershell
.\.venv\Scripts\python.exe champion_solution/solution_torch.py tasks/regression/task.md `
  --output-dir outputs/champion_regression_flaml_v1 `
  --task-type regression --autogluon-budget 0 --flaml-budget 1800 `
  --threads 8 --researchers 1 --training-jobs 1 `
  --reviewer --no-analyst `
  --time-budget 9900 --max-steps 80 --step-timeout 3600 `
  --require-selection --instructions flaml_regression_plan.md
```

Общий бюджет агента — 9900 секунд. До 1800 из него можно потратить на все
FLAML-поиски и внешние refit вместе; это не 1800 на каждую модель/фолд.
Финальный refit использует общий резерв экспорта агента. Один обучающий процесс
получает 8 потоков. Новый код требует новой папки запуска; --resume старых
экспериментов не подходит из-за изменённого fingerprint. compare_regression.py
продолжает использовать старые замороженные копии, поэтому FLAML запускаем этой
отдельной командой. После проверки можно повторить с другим общим бюджетом.

## Схема проверки и экспорт

- Источник — завершённый актуальный одиночный run_temporal_suite, выбранный
  mode baseline/history_exact/history_groups/history_hierarchy. В этой версии
  residual_history, history_gate, ансамбль и классификация как источник запрещены.
- Копируются его временные периоды, строки, ключи истории и параметры сглаживания.
  Без feature_code наследуются исходные признаки; пустая строка означает сырые.
- В каждом внешнем прошлом последняя группа времени становится внутренней
  проверкой. AutoML.fit видит только inner train и inner validation.
  Категориальные уровни и preprocessing обучаются на inner train.
- После выбора точной записи FLAML повторяет рецепт на всём outer train без
  нового поиска, затем оценивается на внешнем году. История для refit считается
  заново, каждая обучающая строка видит только более ранние target.
- Внутренний поиск оптимизирует raw RMSE. Внешняя оценка и экспорт применяют
  прежний сохранённый clipping, как другие temporal-кандидаты.
- Поддержаны LightGBM, XGBoost, Random Forest, Extra Trees и опционально CatBoost;
  первый план явно выбирает первые четыре. GPU/Ray/Spark/MLflow и внутренний
  ансамбль FLAML отключены. Используется статическая начальная конфигурация.
- Результаты попадают в обычный temporal-рейтинг. При проигрыше FLAML сохраняется
  reference, но Qwen должен проверить одну фиксированную равновесную смесь с
  сырым mode="flaml": отдельный проигрыш не исключает пользу для ансамбля.
  blend_temporal_suites принимает 2–4 одиночных suite и явный member_modes.
  Экспорт такого компонента не меняет selected_mode исходного suite.
  Mode reference дублирует источник, его нельзя считать новой независимой моделью.
- Финальный FLAML refit на всём train использует точный рецепт последнего фолда,
  затем сохраняет модель, историю, категориальные уровни и проверяет reload.
  Основной CSV публикуется существующим finalize_selected.

У каждого поиска есть общий бюджет/ledger, lock и дочерний watchdog: FLAML
сам не гарантирует жёсткого дедлайна refit. После убийства незавершённый резерв
не возвращается автоматически. Кэш готового suite не обучается и не списывает
бюджет. Неполные логи сохраняются для диагностики. Неудачный кандидат не заменяет
предыдущий submission; ошибка остаётся в ledger и итоговом аудите.

## Результаты

В outputs/champion_regression_flaml_v1/agent_runs/<run>:

- flaml_summary.json — парное сравнение и выбор;
- flaml_budget.json — резерв, фактические затраты и ошибки;
- temporal/<suite>/plan.json, report.json — условия и внешние метрики;
- temporal/<suite>/flaml_fold_* — выбранные рецепты, модели и журналы поиска;
- run_summary.json — общая история, победитель и фактический экспорт.

Основные предсказания появятся в outputs/champion_regression_flaml_v1/submission.csv.
Файл требует сохранённого кода/окружения для повторной загрузки модели; для
FLAML-suite также сохраняйте его reference и журналы, если нужен повторный refit.
Локальные модели/данные/JSON не упаковываются в платформенный ZIP. Новый модуль
flaml_research.py добавлен в список корневых .py сборщика; requirements уже
содержал flaml[automl]==2.3.6.

Источники интерфейса: [FLAML 2.3.6](https://github.com/microsoft/FLAML/blob/v2.3.6/flaml/automl/automl.py),
[обработка данных](https://github.com/microsoft/FLAML/blob/v2.3.6/flaml/automl/task/generic_task.py).

В платформенной сборке v7 FLAML получает 1800 секунд на регрессию по умолчанию.
Локально прежний default 0; включение через --flaml-budget 1800. Для классификации
FLAML отключён, AutoGluon имеет отдельный платформенный бюджет 3600 секунд.
