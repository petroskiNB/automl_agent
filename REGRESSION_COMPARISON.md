# Изолированная проверка регрессии

Контроль — точный ZIP с общим баллом платформы 2157.225. Этот балл относится
к двум задачам вместе: отдельная платформенная RMSE неизвестна. Контрольный
архив не меняется. В рабочем коде исправлены выбор режима и настройки AutoGluon:

- Профиль определяется по разделу задачи в task.md либо явно через --task-type.
  Неоднозначное описание не включает AutoGluon автоматически.
- Для регрессии бюджет AutoGluon всегда 0, включая платформенный запуск
  и переданный положительный --autogluon-budget. Проверка его установки,
  дополнительные инструкции и инструмент не попадают в регрессию.
- Для классификации платформенный бюджет остаётся 3600 секунд; локальный
  запуск требует явного включения. Обучение и экспорт классификации сохранены.
- Основной промпт и схемы инструментов регрессии совпадают с контролем 2157.225.
  Это восстановление контрольного пути, а не новая модель или обещание роста RMSE.
  Общая инфраструктура экспорта и аудита остаётся текущей.

## Сравнение через Qwen

Подготовка уже выполнена в outputs/regression_comparison_20261025. Сохранены:
точные исходники контроля, снимок текущего кода и одинаковые входные файлы.
Можно менять рабочий код после подготовки: сравнение использует сохранённые копии.
Не редактируйте сами копии внутри папки сравнения.

В PowerShell из корня проекта, после задания API:

```powershell
.\.venv\Scripts\python.exe compare_regression.py --run both
```

Два запуска идут последовательно. Каждый: 8 потоков, одно обучение, один
исследователь и reviewer, без analyst; 9900 секунд, 80 шагов, step timeout 1800.
Одинаковый бюджет не заставляет использовать всё время: остановка по плато,
ограничению шагов или ошибкам API остаётся возможной. Это два отдельных бюджета.
Qwen и измеренное время недетерминированы; один повтор не доказывает превосходства.

Для раздельного запуска используйте вместо --run both:

```powershell
.\.venv\Scripts\python.exe compare_regression.py --run control
.\.venv\Scripts\python.exe compare_regression.py --run isolated
```

Начинаем без --resume и без импорта прошлой истории: это одинаковые начальные
условия. Встроенные контрольные рецепты доступны обеим версиям; их старые оценки
не засчитываются как новый эксперимент. История внутри каждого запуска сохраняется.
После аварии не перезапускайте ту же сторону сравнения: подготовьте новую папку.

Скрипт проверяет хеши исходников/данных и совпадение Python, версий основных
пакетов, модели Qwen и API URL. Ключ не записывается. До --run API не используется.

```powershell
.\.venv\Scripts\python.exe compare_regression.py --report
```

Отчёт comparison_report.json создаётся также автоматически после запуска.
Сравнение разрешено только для успешно опубликованных temporal pipelines:
одинаковые данные, задача, временные периоды, сохранённые train/validation индексы
и политика клиппинга. Случайный holdout не подставляется вместо temporal RMSE.
Проверяется, что в каждом фолде train строго раньше validation.

Смотрим mean RMSE, последний и худший периоды; разность isolated - control
отрицательна при улучшении. Также смотрим затраченное время, выбранный pipeline
и пропущенные этапы. Оба поиска адаптивно используют эти периоды: скрытый тест
платформы остаётся отдельной проверкой.

Логи: control.log и isolated.log. Предсказания: control/submission.csv и
isolated/submission.csv. Полная история: соответствующие agent_runs.

Для нового повтора или изменения бюджета:

```powershell
.\.venv\Scripts\python.exe compare_regression.py --prepare --folder outputs/regression_comparison_repeat2 --time-budget 9900
.\.venv\Scripts\python.exe compare_regression.py --run both --folder outputs/regression_comparison_repeat2
```

Старый локальный ориентир до этого сравнения: mean RMSE 40.70177,
последний год 34.51227, худший год 52.37795 (периоды 3, 4, 5;
outputs/champion_regression_v5/agent_runs/20261024_183405_297925,
history_hierarchy). Это не индивидуальная метрика платформенного контроля.

## LightAutoML и FLAML как следующие кандидаты

Это локальные AutoML-системы: выбирают, настраивают и иногда объединяют модели.
Qwen остаётся исследователем, а AutoML станет ещё одним ограниченным по времени
инструментом рядом с train_model и run_autogluon_suite.

FLAML делает акцент на экономном поиске семейств/параметров. Можно ограничить
список, например LightGBM, XGBoost и лесами, задать time_budget и n_jobs;
ансамблирование включается отдельно. LightAutoML строит табличные pipelines
с обработкой признаков, проверкой и объединением моделей; доступны ограничения
timeout и cpu_limit. Набор моделей зависит от версии и выбранного preset.

План интеграции после сравнения регрессии:

1. Один дополнительный кандидат FLAML с фиксированным общим бюджетом,
   затем отдельным экспериментом LightAutoML. Не включать все системы сразу.
2. Внешние периоды 3/4/5 остаются оценочными. Для каждого периода AutoML видит
   только прошлое; поиск/early stopping происходят внутри этого прошлого.
   Внешний validation нельзя передавать как tuning_data/X_val для подбора.
3. Исторические признаки считаются заново внутри внутренних и внешних временных
   разбиений. Нельзя один раз посчитать target-агрегаты на всём train, а потом
   передать обычному случайному CV. Случайные фолды по умолчанию сюда не подходят.
4. Сохраняем прогнозы на тех же внешних строках. Сначала сравниваем отдельный
   кандидат; затем фиксированное усреднение с контрольным pipeline. Настраиваемые
   веса требуют внутренней калибровки. Для классификации аналогично сохраняем
   вероятности, единый порядок классов и внутреннюю настройку Macro F1.
5. Выделяем резерв на финальный refit/экспорт и проверяем перезагрузку модели.
   Новые инструменты пока НЕ реализованы и не подключены этим изменением.
