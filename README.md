# Агент AutoML: управляемые эксперименты

Проект для трека AutoML Альфа-Хака. Qwen через API выбирает эксперименты;
CatBoost/LightGBM обучаются локально, а при проверке — на платформе организаторов.
Qwen не дообучается. Ключ общий для команды, запросы расходуют общий бюджет.

## Быстрый старт для команды

1. Склонируйте репозиторий через `git clone <URL_репозитория>` и откройте его папку
   в терминале. URL возьмите в вашем Git-хостинге.
2. Установите Python **3.12**. На Windows можно выполнить
   `winget install --exact --id Python.Python.3.12`, затем открыть новое окно PowerShell.
   Проверка: `py -3.12 --version`.
3. Создайте окружение и установите зависимости по разделу ниже. Для обоих
   алгоритмов установите также LightGBM.
4. Скачайте данные у организаторов и разложите их по структуре ниже. Данных
   и логов в Git нет — каждый участник скачивает их отдельно.
5. Выполните проверки `--check` и тесты, затем проверьте API через `check_api.py`.
6. Задайте переменные подключения и запускайте задачи по одной.

```text
automl_agent/
├── solution.py              # Контроллер и API-цикл
├── research.py              # Обучение, метрики и выбор лучшей модели
├── check_api.py             # Один короткий запрос для проверки подключения
├── build_submission.py      # Сборка ZIP по явному списку файлов
├── requirements.txt         # Исходный список организаторов для платформы
├── test_solution.py
├── test_research.py
└── tasks/                   # Локальная папка, не отправляется в Git
    ├── regression/
    │   ├── task.md
    │   ├── train.csv
    │   ├── test.csv
    │   ├── data_dictionary.csv
    │   └── sample_submission.csv
    └── classification/      # Такой же набор из пяти файлов
```

`solution.py` управляет Qwen и временем. `research.py` выполняет обучение,
расчёт метрик и сохранение лучшего результата. MCP не требуется.

Инструменты агента:
- `inspect_data`: структура, пропуски и словарь данных;
- `configure_task`: цель, метрика и неизменное разбиение на весь запуск;
- `train_model`: эксперимент CatBoost или LightGBM, метрика, сохранение победителя;
- `run_python`: дополнительный анализ с генерацией кода.

Оценка и сохранение встроены в train_model: отдельного агента для этого нет.
Поддерживаются задачи с одним таргетом и метрики RMSE, MAE, Macro F1, Accuracy.
Вероятностные метрики, многомерный выход и другие виды задач пока не реализованы.
Схему валидации выбирает Qwen; контроллер фиксирует индексы и проверяет базовые
условия, но не может гарантировать предметную корректность выбранного разбиения.
Для временного разбиения колонка должна сортироваться хронологически (числовой
период или ISO-дата); произвольные строки дат пока автоматически не преобразуются.

## Подготовка

Установите Python 3.12. В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install openai==1.68.2 numpy==1.26.4 pandas==2.2.3 scikit-learn==1.5.2 catboost==1.2.8
```

Это минимальная локальная установка. Исходный `requirements.txt` организаторов
сохранён без изменений. Для полного окружения платформы зависимости нужно
установить из него и проверить совместимость отдельно.

Для экспериментов LightGBM дополнительно:
```powershell
.\.venv\Scripts\python.exe -m pip install lightgbm==4.6.0
```

## Проверка без расходов на API

```powershell
.\.venv\Scripts\python.exe solution.py tasks/regression/task.md --check
.\.venv\Scripts\python.exe solution.py tasks/classification/task.md --check
```

## Подключение и первый запуск

Сначала можно выполнить `.\.venv\Scripts\python.exe check_api.py`.
Он запросит ключ скрыто и отправит короткий запрос; ключ не сохраняет и
переменные окружения для агента не задаёт.

Ключ вводится скрыто и не сохраняется в файле или истории команд:

Первую строку выполните отдельно, вставьте ключ в запрос ввода и нажмите Enter.
Только после этого выполняйте остальные строки в том же окне PowerShell.

```powershell
$secureKey = Read-Host 'API key' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $secureKey).Password
$env:OPENAI_BASE_URL = 'https://changellenge.up.railway.app/v1'
$env:OPENAI_MODEL = 'qwen/qwen3.8-27b'
.\.venv\Scripts\python.exe solution.py tasks/regression/task.md
```

Следующим запуском можно заменить путь на `tasks/classification/task.md`.
Ключ действует только в этом окне PowerShell и его дочерних процессах.
Файл `.env` автоматически не читается.

Для классификации:
```powershell
.\.venv\Scripts\python.exe solution.py tasks/classification/task.md
```

Не запускайте две копии агента одновременно в одной папке задачи: они могут
перезаписывать один submission.csv. API-ключ не отправляйте в чат или Git.
После закрытия PowerShell переменные нужно задать снова.

На Linux/macOS создайте окружение через `python3.12 -m venv .venv`, используйте
`.venv/bin/python` вместо Windows-пути. В Bash ключ можно задать скрыто:
```bash
read -rsp 'API key: ' OPENAI_API_KEY; echo
export OPENAI_API_KEY
export OPENAI_BASE_URL='https://changellenge.up.railway.app/v1'
export OPENAI_MODEL='qwen/qwen3.8-27b'
.venv/bin/python solution.py tasks/regression/task.md
```

По умолчанию: 20 шагов, 30 минут на запуск, 10 минут на один эксперимент,
450 секунд резерва на финальное обучение и минимум 4 успешных эксперимента
перед добровольным завершением Qwen. Лимиты времени/шагов имеют приоритет над
минимумом экспериментов. После 4 экспериментов агент может завершиться раньше.
Резерв ограничивается 30% общего бюджета. API-запросы не повторяются автоматически.
Таймаут API не является строгим общим дедлайном; оставляйте запас до 3 часов.
Запуск расходует общий бюджет ключа. Скрипт не считает стоимость запросов.

Более длительный запуск после проверки короткого:
```powershell
.\.venv\Scripts\python.exe solution.py tasks/classification/task.md --time-budget 9900 --final-reserve 1800 --step-timeout 1200 --max-steps 60 --min-experiments 6
```

Сначала автоматически сохраняются предсказания лучшей модели, обученной на
обучающей части. В конце контроллер переобучает её на полном train с теми же
параметрами. Если переобучение прервано, ранний CSV остаётся доступен.
Сравнение выполняется на неизменном holdout; повторное использование одного
holdout для многих гипотез может привести к подгонке под него.
Пока применяется заданное число деревьев без early stopping — начинайте с
100–200 деревьев. Срок выполнения ограничен процессом, потоки обучения — 8.

Результат: `submission.csv` рядом с `task.md`. В `agent_runs/` сохраняются
код шагов, stdout/stderr и история сообщений. Предыдущий submission переносится
в каталог текущего запуска, чтобы не принять старый результат за новый.

Дополнительно в каждом запуске:
- `events.jsonl`: параметры и результаты вызовов инструментов, включая ошибки;
- `research/state.json`: успешные эксперименты, метрики и выбранный победитель;
- `research/split.npz`: фиксированные индексы train/validation;
- `research/model_*.joblib`: модели экспериментов;
- `research/final_model.joblib`: модель после полного переобучения (если успешно).

Новый запуск начинает новое исследование; автоматическое продолжение не реализовано.
Модель в joblib теперь хранится в словаре вместе с параметрами кодирования категорий.
Безопасно загружать только собственные доверенные joblib-файлы.

Генерируемый код исполняется с правами вашего пользователя. Отдельный процесс
и удаление ключей из его окружения не являются песочницей. Для изоляции
следующий этап — запуск в контейнере с доступом только к каталогу задачи.

Пути в оригинальных task.md могут отличаться от вашей раскладки: агенту
дополнительно передаются найденные реальные пути. Исходные условия не изменены.

Для платформы в корне ZIP нужны solution.py, research.py и исходный requirements.txt.
Данные, локальное окружение и логи в ZIP не включайте. Полный запуск и
соответствие ограничениям платформы нужно проверить до отправки.

## Локальные тесты без API

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Тесты выполняют короткие обучения на искусственных данных и проверяют цикл с
имитацией ответов API. Это не измерение качества на задачах хакатона.

## Сборка и первая отправка

После проверки обеих задач из корня проекта:
```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe build_submission.py
```

Загрузите `outputs/automl_submission.zip` в форму решения трека AutoML.
Сборщик проверяет состав ZIP, целостность и соответствие файлов исходникам.
Внутри ровно три файла в корне: `solution.py`, `research.py`, `requirements.txt`.
Весь каталог проекта архивировать нельзя: там данные, модели и окружение.
После изменения кода пересоберите архив; ранее созданный ZIP сам не обновляется.

Платформа запускает `python3 solution.py task.md` и подставляет переменные API.
Предсказания и модели, полученные локально, не отправляются. На платформе агент
проводит новое исследование, поэтому результаты могут отличаться.
Первая версия ZIP использует проверенные настройки по умолчанию: 30 минут,
20 шагов, резерв 450 секунд. Локальные флаги командной строки в ZIP не сохраняются.
Полная установка requirements в Linux/Docker пока отдельно не проверена.

По инструкции организаторов: ZIP до 100 МБ, до 3 часов на задачу, 8 CPU,
32 ГБ RAM, до 3 сабмитов команды в день. Согласовывайте отправки внутри команды.

Проверенные локальные результаты на 21.10.2026:
| Задача | Лучшая модель | Валидация |
|---|---|---|
| Регрессия | LightGBM | RMSE 42.90935 |
| Классификация | CatBoost, SqrtBalanced | Macro F1 0.63660 |

Это не оценки платформы и не гарантированный результат следующего запуска.

## Git: что отправлять

В Git нужны исходники, тесты, README, requirements и .gitignore.
Данные, модели, архивы, виртуальные окружения, ключи и логи исключены правилами
`.gitignore`. Небольшие итоговые метрики удобно записывать в README или отдельный
Markdown-отчёт вместо загрузки моделей и полных журналов.

Перед коммитом проверьте:
```powershell
git status --short
git diff --cached --stat
git ls-files
```

`.gitignore` не действует на уже отслеживаемые файлы. Если ранее добавили,
например, папку tasks, уберите только её из индекса через
`git rm -r --cached -- tasks` и закоммитьте изменение. Локальные файлы останутся.
Это не удаляет большие файлы из старых коммитов. Если ключ уже попал в историю,
его необходимо отозвать/заменить; одного удаления файла недостаточно.

## Частые ситуации

- `No suitable Python runtime found`: установите 3.12 и заново откройте терминал.
- `ModuleNotFoundError`: устанавливайте пакет через Python именно из `.venv`.
- Не задан API-ключ: задайте переменные в том же терминале, где запускаете агента.
- `Budget has been exceeded`: общий лимит ключа исчерпан; по инструкции сброс в 03:00 МСК.
- Ошибка/таймаут API: исследование прекращается; если есть успешный эксперимент,
  контроллер пытается выполнить финальное обучение и сохранить результат.
- Таймаут одного эксперимента: его процесс останавливается, агент получает ошибку;
  результаты предыдущих успешных экспериментов остаются.
- CSV прошёл проверку: подтверждён формат, а не качество на скрытом тесте.
