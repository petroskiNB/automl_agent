# План общего поиска

1. Начни с быстрого бустингового baseline; при resume прочти существующие эксперименты
   и не повторяй их. Сохрани полный feature_code при наследовании рецептов.
2. Features улучшает признаки бустинга, models проверяет компактную MLP и отвечает
   за OOF/финал, rare исследует веса классов и ошибки сети/бустинга. Разные роли
   не должны одновременно выполнять один рецепт. После baseline сравни MLP
   width=128, layers=2, iterations=40, batch_size=512, learning_rate=.001,
   dropout=.1, weight_decay=.0001, seed=42. Сначала SqrtBalanced, затем без весов
   при наличии бюджета. Для сети не передавай параметры деревьев.
3. Используй run_classification_suite на 3 одинаковых внешних фолдах для лучших
   бустинга и сети. Оцени одиночные модели, равную смесь и правило Macro F1,
   обученное только внутри фолдов. Проверь adversarial stress split. Отчёт должен
   показывать среднюю, худшую метрику и качество редких классов, а не только holdout.
4. Не включай сеть, если ансамбль не улучшает проверку. Для финала явно вызови
   select_final_candidate и finalize_selected. Оставь резерв времени для экспорта.
   Не возвращайся к заведомо худшему fallback только из-за слишком строгих порогов:
   объясни компромисс по внешним фолдам и stress и выбери проверенный вариант.

Результаты синтетического теста не являются оценкой этой задачи. Старый holdout
многократно использовался для поиска: небольшой выигрыш на нём не доказательство.
