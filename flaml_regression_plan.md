# Проверка FLAML на временной регрессии

Цель: проверить один новый AutoML-кандидат на тех же внешних периодах и
понять, добавляет ли он качество/разнообразие к сильным историческим пайплайнам.
Не меняй схему проверки ради более красивого числа. Все пояснения — по-русски.

1. Прочитай inspect_data и inspect_research_plan, сверь словарь. Для этих данных
   test Year_Factor=6, train=1..5: configure_task regression/rmse/time/Year_Factor.
   Нужны внешние периоды 3/4/5; обучение/подбор внутри каждого используют прошлое.
2. Сделай короткий baseline и повторно измерь применимый train_reference_recipe.
   Получи один сильный ОДИНОЧНЫЙ run_temporal_suite с history_hierarchy=True,
   предложенными ключами/backoff и smoothing=20. Исторические баллы не засчитывай
   как измерения нового запуска. Для source FLAML не подходят ансамбль,
   history_gate или residual_history как выбранный mode.
3. Сразу после появления такого source вызови run_flaml_suite:
   reference_suite_id=<актуальный одиночный suite>, time_limit=1800,
   estimator_list=["lgbm","xgboost","rf","extra_tree"]. Feature_code сначала
   НЕ задавай: так наследуются признаки reference и сравнивается новый поиск
   моделей при одинаковой схеме признаков/истории. Пустая строка явно переключает
   на сырые признаки и должна быть отдельной гипотезой.
4. Это общий бюджет на все внешние фолды: внутренние поиски и refit вместе.
   Не передавай внешние validation/test в fit и не запускай FLAML через run_python.
   FLAML сам обучает семейства/настраивает параметры внутри прошлого; его
   встроенные stacking/ensemble и случайное разбиение не используются.
   Внутренний поиск минимизирует raw RMSE, внешний score и экспорт используют
   сохранённую политику клиппинга; значения разных схем не сравнивай напрямую.
5. В отчёте сравни reference и flaml: mean_rmse, latest_rmse, worst_rmse,
   выбранные семейства по периодам и время. Критерий итогового выбора прежний:
   минимум mean_rmse, затем latest_rmse, worst_rmse. Mode reference — это точная
   копия исходного кандидата; не учитывай её как независимую модель в ансамбле.
6. Если FLAML выиграл, проверь blend_temporal_suites с сильным отличающимся
   одиночным suite на этих же строках. Веса фиксированные равные. Сравни весь
   глобальный temporal-рейтинг; не выбирай более слабый ансамбль только потому,
   что в нём есть новый инструмент. Ошибка FLAML должна быть отражена явно;
   сохраняй успешный reference, если повтор не имеет обоснованного исправления.
7. После нового кандидата продолжи ограниченный поиск по оставшемуся бюджету и
   pending этапам. Сохрани резерв на финальный refit. Явно выбери глобального
   победителя через select_final_candidate(kind="temporal", suite_id=...).
   finalize_temporal сохраняет отдельного кандидата; основной submission.csv
   опубликует контроллер через finalize_selected. Проверку главного CSV до этой
   публикации нельзя выдавать за проверку выбранного финального ансамбля.

Локальные ориентиры предыдущего сравнения: контроль mean 39.927404,
latest 36.309228, worst 50.497232; изолированный поиск mean 40.094317,
latest 35.860475, worst 51.036186. Это адаптивная временная валидация,
не скрытый тест платформы, не гарантия результата и не основание подставить
числа вместо нового обучения. Контрольный ZIP остаётся неизменным.
