# Продолжение классификации: сравнение XGBoost

Продолжай существующее исследование с замороженным разбиением и Macro F1.
Текущий победитель №11: CatBoost, Macro F1 0.6283574694. Прочитай его полный
рецепт и метрики классов через read_experiment. Сохраняй победителя, пока новый
вариант не улучшит основную метрику.

Дополнительный исторический ориентир: в запуске 20261021_213836_723418 опыт №8
дал Macro F1 0.6366048114 на тех же индексах разбиения. У старого запуска нет
контрольных сумм входов, поэтому воспроизведи рецепт через train_model и сравни
заново: catboost, исходные признаки (feature_code=""), iterations=500, depth=7,
learning_rate=0.05, l2_leaf_reg=3, random_strength=1, auto_class_weights="SqrtBalanced",
early_stopping_rounds=0. Историческую оценку не импортируй как новый эксперимент.

Теперь train_model поддерживает algorithm="xgboost".
1. Обучи начальный XGBoost на исходных признаках с полными строковыми категориями,
   depth=4, iterations=500, learning_rate=0.05, l2_leaf_reg=3,
   min_child_weight=5, subsample=0.8, colsample_bytree=0.8, early_stopping_rounds=50.
2. При тех же параметрах сравни отсутствие весов, SqrtBalanced и Balanced.
   Обрати внимание на F1 классов Backdoor, Analysis, DoS и Shellcode.
3. Для лучшего варианта сравни исходные признаки и feature_code опыта №11.
   Не считай отношения логарифмированных значений физическими отношениями байтов:
   это отдельные математические признаки. Не делай выводов о потолке качества.
4. Затем проверь 2–3 обоснованные вариации глубины или регуляризации. Используй
   min_child_weight вместо min_child_samples; num_leaves и random_strength не доступны.
5. Сравни лучший XGBoost с CatBoost №11 и ограниченным числом ансамблей вероятностей
   с равными весами. Ухудшение ансамбля допустимо: оставь одиночную модель, если лучше.
6. В итогах укажи Macro F1, показатели слабых классов и время. Редкий класс Worms
   имеет мало объектов на валидации, не делай устойчивых выводов из единичных ошибок.

Число итераций выбирает инструмент по Macro F1 без весов валидации. Финальное
переобучение с выбранным числом деревьев и публикацию выполняет контроллер.
Это план для классификации; временную колонку нельзя выдумывать ради validate_experiment.
